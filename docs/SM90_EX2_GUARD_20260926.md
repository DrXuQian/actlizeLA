## What the generated code actually did

The current CUDA12.8 standard `exp2f` image has an `x < -126` predicate,
optional RN multiplication by 0.5, one MUFU.EX2, and optional RN squaring.
FI's fastmath path uses direct MUFU, but silently replacing our standard
function would change the subnormal contract. PTX explicitly specifies the
subnormal behavior of `ex2.approx.ftz`; this is not a universal identity with
standard `exp2f`. See the [official PTX EX2 specification](https://docs.nvidia.com/cuda/parallel-thread-execution/index.html#floating-point-instructions-ex2).

S25 uses the existing gate warp to reduce finite min/max across **all 64
initialized prefix positions**, including padding. If the rounded span is
strictly below126, every rounded pair difference exceeds-126, even for
nonmonotone prefixes. It publishes a stage-local flag before the same alpha
pipeline commit. The auxiliary reader accesses it between its existing wait
and release. Wide/nonfinite ranges retain the standard fallback. No extra
warp, helper kernel or changed producer/consumer arrival count.

That proof was correct, but the desired compact branch did not materialize:

- **S25:** the compiler if-converts two whole epilogues, increasing whole-body
  static EX2 sites64->124. All four specializations get112B stack, versus
  S24's24/32B. Spill stores274–294B and loads276–424B. Some correction
  instructions remain predicated on secondary predicates rather than simply
  disappearing with the outer guard. This fails the intended compact-codegen
  goal. Its timing is a retained negative counterfactual, not an admitted fast
  implementation. A particular spill's isolated latency is not established.
- **S26:** independently from S24, stage KK*beta, then QK/KK decay products,
  then final masks/casts. Standard EX2 and live-lane multiplication order stay
  fixed. Full/tail pre-inverse intervals547/610->553/635 static sites. Tail
  code loses60 FSEL but gains15 F2FP,45 PRMT and28 MOV sites; do not claim that
  conversion cost is invariant just because the mathematics is. Stack16/32B,
  spill loads/stores16/32B, versus20/28B spills on S24: not a uniform resource
  win. Timing fails to establish a speedup.
- **S27:** retain S25's range proof but express one native data path: optional
  RN half, one EX2, optional RN square, with correction predicate
  `!normal_span && x < -126`. This restores64 static EX2 sites and24/32B stack.
  However, the compiler lowers the guard into60 auxiliary
  `FSETP.LT.AND ... -126, !P2` sites across full/tail bodies. **Those comparisons
  still execute.** The code is compact again, not comparison-free; timing does
  not improve. Matrix/math/data-protocol opcode families remain unchanged.

These are **static sites**, not dynamic instruction counts or cycle costs.
Native gates examine all four dtype/initial-state specializations, not one
favorable symbol. Actual remote `launch.o` and local instruction streams,

the separate standard function. Unconditionally using direct EX2 produces

exhaustive claim over all2^32 floating-point inputs or other toolchains.
