# ZW890 / PPU1.5 forward GDN

Status: source integration and native compilation; **device admission UNVERIFIED**.
No ZW890 numerical results or performance figures are claimed by this change.

## Use

Run in the matching PPU SDK/PyTorch container, not an NVIDIA PyTorch container
with a different runtime library added to `LD_LIBRARY_PATH`:

```bash
git pull --ff-only
PPU_SDK=/usr/local/PPU_SDK DEVICE=0 JOBS=8 bash tools/run_ppu15_gdn_box.sh
```

The runner creates `/workspace/actlize-la-zw890-<sha>-<UTC>/` with the binary
hashes, compiler identity, source diff, native ISA/resources and device logs.
`results.tar.gz` contains the evidence, **not** the SDK or full build tree.
There are no mandatory hand-entered identity variables and no remote build.
Native primitive failure stops the run before full GDN or timing.

For build only:

```bash
PPU_SDK=/usr/local/PPU_SDK BUILD_DIR=/workspace/actlize-la-ppu15-build \
  bash scripts/build_ppu15.sh
```

Install the Python frontend if using it outside the checkout:
`GDN_QSA_TARGET=python python -m pip install --no-build-isolation --no-deps -e .`.
Set the extension path from that build (replace the ABI suffix as appropriate):

```python
import os
os.environ["GDN_QSA_PPU15_EXTENSION"] = "/workspace/actlize-la-ppu15-build/_gdn_residual_ppu15.cpython-312-x86_64-linux-gnu.so"
from actlize_la import gdn_forward
o, ht = gdn_forward(q, k, v, g, beta, initial_state=h0,
                   output_final_state=True, backend="ppu15")
```

`algorithm="residual"` is equivalent to `auto` on this target. Legacy
`delivery="full-chunk"` is not a PPU1.5 option: native full-C64 versus guarded
tail is selected from T internally. Other algorithms fail without fallback.
`mode="perfmodel", sm_count=20` preserves the existing no-device-profile
metadata behavior; it does not pretend a simulated run is a device result.

## Scope and boundaries

| Component | PPU1.5 implementation |
|---|---|
| API | Q/K BF16 `[B,T,Hk,128]`; V BF16 `[B,T,Hv,128]`; Hv divisible by Hk |
| Gates | BF16 or FP32 natural-log g; BF16 beta; no implicit activation/normalization |
| State | Optional FP32 initial and final `[B,Hv,K,V]`; BF16 output; forward only |
| Algorithm | C64 prefix → gated KKT/inverse → recurrent residual state → chunk-parallel output |
| Inverse | Ordered static FP32 diagonal; three TF32 high/residual products for block merges |
| State | V32 per CTA, 8 warps, reused gate coefficients, full-C64/tail specialization |
| Primitives | Native PPU0015 BF16/TF32 warp MMA + paired AIU/SWZL |
| Dependency | `third_party/actlize` at the existing pin; no PPU CUTLASS3.6/10700 dependency |
| Not included | Original reset/scan, materialized WY, FP16, backward, new fastmath, PPU1.7 algorithms |

The numerical algorithm is the retained PPU1.0 residual formulation, not a
reset approximation. R, Vnew, scaledV and H snapshots retain their separate
BF16 boundaries; accumulation and live H remain FP32. Output includes the same
`1/sqrt(128)` scale. Gate values never decide which algorithm runs.

PPU1.5 does **not** share the PPU1.0 fragment ABI. Its A/C register order
differs at 224/256 C coordinates. TF32 A/B also need distinct maps. The new
layout uses the pinned PPU0015 CuTe traits, verified against independent
coordinate equations. The AIU producer and SWZL reader share SW128/SW64 cube
layouts; an A reader uses `Swap=false`, B uses `Swap=true`. Transpose changes
the reader, not a separately materialized transpose kernel.

Source cross-check for this pair: FA-sail `hopper/mainloop_fwd_sm80.hpp`
at `f6005910425265c17478bea8a6584e63709956bb`, file SHA256
`1f780ca2d21177b75ed7d092d8457bb4f838ec4d21d865a992cfd641a8cd5edf`.
It is a reference, not a runtime dependency or a substitute for device tests.

Private P is compact `[group,64,64]`, H snapshots are `[group,V,K]`, Vnew is
`[group,V,T]`. These are three disjoint allocations. Public state stays K-by-V.
Offsets are elements; AIU `stride_w` is explicitly the element pitch. Unlike
the older inverse workspace, compact P does not borrow the padded H pitch.

Source ownership is deliberately small:

- `layout.cuh` / `primitives.cuh`: target-specific register and shared ABI.
- `prepare.cu`, `state.cu`, `output.cu`: complete residual forward stages.
- `launch.cu` / `bindings.cpp`: orchestration, input validation and current stream.
- `gdn_ppu15_interface.py`: lazy loading, no hardware-generation guessing.
- `cmake/backends/ppu15.cmake`: explicit source list and true shared-library link.

No PPU1.0 kernel, scheduler, tuned candidate or NVIDIA implementation is changed.
Only the shared compiler-spelling resolver gains a second explicit logical
target: `ppu_15` / `ppu0015`, both checked against device arch150. An SDK/header
failure cannot fall back to ppu001 or another architecture. Build directories
cannot be reused across targets. Do not symlink `libhggcrt.13` to `.12` to make
an incompatible container load an old DSO; rebuild with the installed SDK.

## Validation and limits

Local SDK2.1.1 compilation of the real bodies produced:

| Native body | Registers | Stack bytes |
|---|---:|---:|
| Prefix | 32 | 0 |
| Solve | 96 | 0 |
| Full-C64 state | 160 | 0 |
| Guarded-tail state | 168 | 0 |
| Output | 96 | 0 |

These are compiler-resource observations, not occupancy or timing predictions.
The PPU1.0 register counts/performance cannot be transferred to ZW890.
Native ISA contains `v.mm.f32.bf16.m16n16k16`, TF32 MMA, AIU and SWZL loads.
The native checker requires all five bodies and rejects absent math, a missing
tail body, stack use, wrong generations or traps. Do not count this as a
numerical/device PASS.

The local host layout gate exhausts 20,480 shared cells, all native A/B/C/TF32
register maps and state/V/output ownership. Planting the PPU1.0 C ABI is red.
Other negative controls reject wrong-image loaders, incompatible build targets,
ignored delivery selectors, missing native math/body and stack fallback.

Regression checkpoint: **109 Python host checks and 27 CTest checks PASS**
(the latter include the native PPU1.5 layout and expected-red old-C-map case).
The existing PPU1.0 source bodies and NVIDIA routing are preserved.

Local full extension linking and Torch-based numerical tests are **SKIP**:
the current local SDK has no usable `libhg_wrapper` and the local Python has no
PyTorch. Native device object compilation is tested; linking is not claimed.
The box build requires the real libraries and uses `--no-undefined` for the
multi-TU device library. Missing prerequisites do not become a green build.

The box admission is fixed before measurement:

1. Independent primitive tests: AIU and manual writers, SW64/SW128, strided
   input, full/tail padz, A/B/AT/BT, BF16 and TF32 exact integer products.
2. 40 complete-forward cases: T1/63/64/65/127/128/129/2048/2049,
   GVA1:1/1:2/1:4, zero/nonzero state, BF16/FP32 gates, strong/weak/variable
   decay. Both output and state use the existing independent recurrent oracle
   and unchanged **2% max-absolute / reference-max** criterion. No claim of
   cross-architecture bit equality. Within one target, eight launches, GVA
   expansion and output-only calls must be RAW-BIT stable; inputs immutable.
   Zeroing output or state must fail the oracle.
3. Complete-forward timing for B1/T2048/Hk16/Hv32, Hv64, and B2/Hv32,
   each with g=-0.1/-1. Each timed fixture is independently checked first.
   These event spans include host launch gaps; they are not ACU kernel sums
   and are not a claim to beat FLA. No performance threshold is invented
   before the first ZW890 run.

The local register/shared checks admit a buildable bring-up, not a ZW890
performance winner. Next device evidence decides whether native layouts,
resources or scheduling need tuning on 890 itself.
