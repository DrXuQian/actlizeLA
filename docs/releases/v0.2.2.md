# actlizeLA 0.2.2

Forward-only GDN/QSA serving integration, default retained PPU1.0 GDN, and a
complete precompiled serving wheel. This release is authorized for publication
with the outstanding device qualifications listed below; it is not a claim that
all supported architectures or full-model execution have been qualified.

## Included

- GDN prefill, incremental decode, multi-token verify and accepted-prefix state
  commit; explicit FP32 KV/VK layout conversion and caller-owned workspace.
- Paged BF16 QSA with incremental compressed history, causal selection/tails and
  rejection-safe continuation.
- Grouped/gated RMSNorm, HC/PLE pointwise helpers, dilation1/3 ShortConv and
  speculative history transport, with versioned native C launch interfaces.
- Public PPU1.0 GDN and prepared serving use the retained full-chunk/guarded-tail
  residual implementation by default. No extra legacy extension is required for
  the complete wheel. NVIDIA backends and explicit diagnostic selections remain
  available through their existing build paths.
- File-only library discovery, sealed resource identities and installed-only
  qualification. No installation-time compiler, device probe or dependency
  download; platform Torch and runtime are not bundled or replaced.

## Binary and installation

The attached wheel is **PPU1.0 / SDK 2.2.1-184ee6, runtime API v3**, Linux x86_64.
Use the matching SDK/driver/container; the native runtime requires the matching
OS C/C++ libraries. Python >=3.10; intended integration environment is Python
3.12 and platform Torch 2.9. No PPU1.5, PPU1.7 or NVIDIA binary is attached.

```bash
python -m pip install --no-deps \
  https://github.com/DrXuQian/actlizeLA/releases/download/v0.2.2/actlize_la-0.2.2-1ppu10version221184ee6-py3-none-linux_x86_64.whl
```

`release-manifest.json` and `SHA256SUMS` bind the wheel, source tag, SDK,
submodule, validation records and qualification kit. Verify the artifact hashes
before installation. The library is discovered with
`actlize_la.get_library_path(target="ppu10")`; no manual `.so` path is needed.
See [installation and qualification](../SERVING_WHEEL.md) for source builds and
the complete non-performance device test command.
