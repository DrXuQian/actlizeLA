# Residual V16: more active warps, almost unchanged full-call latency

## Verdict and scope

The user's observations are confirmed: active warps nearly double, bank-conflict
counters increase, and complete kernel time changes little. **BC alone is not
established as the cause.** V16 also duplicates global-to-shared delivery and
shared operand loads. Keep it as a diagnostic arm, not a routing promotion.

Source `5a3ebc9`, PPU-ZW810 72 CU, B1/S2048/Hk16/Hv32/K=V128/C64, captured
g=-1.0. All 15 captured kernels report 1.700 GHz. Same fixture, physical UUID,
loaded extension and device library. Actual capture used
`/sim/eec/shared/junfu.qx/asight/bin/acu`; local SDK re-import is host-only.
All reported times below are ACU kernel times, **not API event spans**.

Archive SHA256 `4e66b340028d2a91abd5e671ed4b7a4d7a09aabc2388041ec11120c8cb5fd92d`:
603 files / 602 hashes / 127 source files verify. Tracked sources clean;
two untracked operator reports are recorded, not build inputs. Device library
SHA256 `fb204130aed69e277be0537d837c85f6fd9a42428655da9a5ae29d69cf2445e9`.
Thirty V16 cases and thirty residual controls, eight repetitions, tails/GVA/
initial-state/output-only pass RAW-BIT and the unchanged independent 2% oracle.
Both gates are numerically admitted; only g=-1 has timing in this bundle.

State improves 2.05%; complete sum improves 0.72%. Unchanged stages are
0.94235 us slower in this capture; do not attribute their variation to V16.
FLA/candidate = 1.00563x, effectively near parity in this single capture, not a
stable speed-win claim. The 1.5x target is 150.44981 us, still 73.96137 us away.

## Occupancy did increase, but ready-to-issue work barely did

| Residual-state metric | V32 | V16 |
|---|---:|---:|
| Grid / threads per CTA | 128 / 128 | 256 / 128 |
| Registers per thread / stack B | 242 / 0 | 98 / 0 |
| Shared B per CTA | 45,568 | 35,328 |
| Achieved warps/CU | 7.08 | 14.12 |
| Achieved occupancy | 11.06% | 22.07% |
| Eligible warps per active cycle (reported WE metric) | 0.25 | 0.29 |
| BF16 MMA executed | 655,360 | 655,360 |
| Dynamic per-PC opcode sum | 14,680,704 | 15,546,624 |
| PU executed counter (different counting scope) | 14,746,240 | 16,070,912 |

The per-PC opcode sum increases 5.90%; the distinct PU counter increases
8.98%. Both are retained, not mixed or silently equated. Per-PC sums close
against the report's opcode-sum metric for all 15 kernels; omitted-PC plants
fail. BF16 arithmetic work is unchanged. Conversions are 1,310,720 vs
1,311,744: V16 additionally converts a zero constant once per launched warp
outside the chunk loop (1,024 executions), not an extra tensor rounding stage.

Memory Dependency ratio is 1.17 -> 2.40, TSM dependency 0.74 -> 1.28,
VMEM dependency 0.29 -> 0.92, commit 0.05 -> 0.14 and sync 0.53 -> 1.34.
These are per-issue ratios with changed active warp population, **not wall-time
shares**. Per-PC memory-dependency samples also do not isolate BC: TSM-wait
samples 5,935 -> 5,477, vector-load waits 2,970 -> 3,661, commit waits 340 ->
809. Sampling populations and mechanisms must not be converted into exact
microsecond attribution.

## The doubled KVD-to-TSM traffic is a real cost

| KVD transaction-byte counters, MiB | V32 | V16 |
|---|---:|---:|
| Global-to-TSM / ldgsts | 112 | 224 |
| Ordinary global loads | 17 | 34 |
| Global stores / KVD-to-L2 writes | 98 | 196 |

MMA and semantic output bytes are unchanged. DRAM read bytes only increase
84,301,568 -> 86,409,472 (+2.50%); doubled on-chip transaction bytes are not
doubled unique input or HBM bytes.

Source byte accounting: 32 chunks per sequence; old 128 CTAs, new 256 CTAs.
Each CTA/chunk executes `Key::stage`, `Inverse::stage`, `Value::stage` in
`csrc/gdn_chunk/gdn_wy_residual[_v16]_ppu.cu`.

| Source payload, MiB | V32 | V16 |
|---|---:|---:|
| K: 64x128 BF16 per CTA/chunk | 64 | 128 |
| P: 64x64 BF16 per CTA/chunk | 32 | 64 |
| V: 64xValueTile BF16 per CTA/chunk | 16 | 16 |
| Logical input payload | 112 | 208 |
| Measured transaction bytes minus payload | 0 | 16 |

K/P duplication explains 96 MiB of the 112 MiB measured increase. The remaining
16 MiB is consistent with each V16 row using half of a 64-byte transaction;
the counter's bytes/transaction ratio is exactly 64. **This residual attribution
is an inference**, not separately observed per-plane traffic: available per-PC
cacheline fields are zero and do not certify it. Do not relabel all 224 MiB as
semantic payload, nor claim a bank-layout fix will remove duplicated K/P.

Useful snapshot/Vnew/final-state writes remain 32+16+2 = 50 MiB; `vmem.st.b32x4`
executions remain 102,400 while KVD store transaction bytes double. Preserve
the distinction between logical bytes and physical transaction amplification.

## BC must be addressed, separately from duplicated work

| Shared metric | V32 | V16 | Change |
|---|---:|---:|---:|
| Total BC counter | 6,930,432 | 7,913,472 | +14.18% |
| Read BC | 2,883,584 | 3,932,160 | +36.36% |
| Write BC | 4,046,848 | 3,981,312 | -1.62% |
| Shared load instructions | 1,429,504 | 1,708,032 | +19.48% |
| Read BC / shared-load instruction | 2.01719 | 2.30216 | +14.12% |
| BC / useful MMA | 10.575 | 12.075 | +14.18% |
| Transposed `ld.swzl` | 524,288 | 786,432 | +50% |
| Non-transposed `ld.swzl` | 393,216 | 393,216 | unchanged |

Source attribution for the additional 262,144 transposed loads: H snapshots
+131,072, residual +65,536, scaled V +65,536. K and P matrix-load totals do not
increase, but K/P global staging does. Smaller V tiles reduce intra-warp reuse
of the transposed operand across independent output-row fragments.

This is not evidence that every shared access acquired worse bank mapping.
The mix and count of loads changed. BC counts and stall ratios do not identify
how much of the 2.56 us state gain was offset by conflicts. Do not infer that
doubling occupancy would otherwise halve latency.

BC elimination is mandatory next work, not replaced by more warps. Target
register-produced H/residual/Vnew/scaled-V halfword stores and transposed
operand reads. PPU C fragments put adjacent output columns in different lanes;
packing BF16 stores is **not** a free reinterpret-cast of one lane's registers.
The user requires **zero added work for BC elimination**: no cross-lane
packing/shuffles, rearrangement kernels, extra copies/barriers or runtime
unswizzling. Use a compile-time CuTe shared layout supported by its native
matrix-load consumer, or native AIU-swzl with matching ld.swzl. Current K/P/V
inputs already use that pair; register-produced intermediates require their
own writer/reader mapping proof. Preserve every BF16 boundary. A constexpr
layout does not erase all thread-dependent address instructions: inspect the
actual native path and reject added remapping work. If the native reader
cannot express a conflict-free layout under this constraint, state the exact
boundary rather than hiding an exchange in compatibility lowering.

## Next design: more warps without doubling global-to-TSM

Keep V32 and grid128. Increase CTA threads128->256, distribute independent
output rows over8 warps, never split reduction K. The proposed mapping is:

```text
column(w)       = (w % 2) * 16
state_row(w,f)  = (w / 2) * 32 + f * 16   [f=0,1]
value_row(w)    = (w / 2) * 16
```

K/P/V staging remains once per CTA; shared remains45,568 B; target logical
global-to-shared remains112 MiB. Launched warps512->1024 without increasing
CTA count. A local compiled design probe uses real native `CLayout`, proves
40,960 output/K-atom cells per CTA identical to the old mapping and rejects
three omitted-warp controls. This proves ownership feasibility, **not** device
codegen, register usage, numerical admission, achieved occupancy or speed.

More warps can still duplicate shared operand loads, so it is not a BC fix.
Reducing register/shared usage alone cannot raise the old grid's ceiling of
128*4/72=7.11 active warps/CU. Keep a bounded 2x2 causal comparison:

- V32 /4 warp /old layout (admitted control).
- V32 /8 warp /old layout (warp-count experiment).
- V32 /4 warp /BC change (layout experiment).
- V32 /8 warp /BC change (combined candidate).

Require unchanged arithmetic/order,8-repeat RAW-BIT output and state, exact
ownership and wrong-permutation negatives, native paired loads and zero spill.
Measure achieved occupancy, useful MMA, KVD-to-TSM bytes, BC per shared request
and complete ACU kernel sums. A lower BC counter without lower latency is a
reported non-win. No kernel or default routing is changed in this review.
Within a fixed warp-count pair, the BC arm must not add dynamic remapping,
traffic, shuffles or synchronization; the8-warp axis is separately attributable.
